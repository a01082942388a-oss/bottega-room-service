그 방향이 오히려 운영하기 훨씬 편해. 각 객실마다 QR을 따로 만들면 객실 수만큼 QR 관리가 필요하고, 객실 변경이나 인쇄물 교체도 번거로워져. QR 하나 → 주문페이지 접속 → 주문 시 객실번호 직접 입력 구조가 관리 측면에서는 훨씬 단순해. 지금 구조에서는 크게 세 군데만 손보면 돼. index.html에서 지금 ?room=301 같은 URL 파라미터로 객실번호를 받는 로직을 제거하거나 선택사항으로 바꾸기 장바구니/주문하기 영역에 객실번호 입력칸 추가 주문 저장할 때 입력된 객실번호를 orders 테이블의 객실번호 필드에 저장 추천 UI는 주문 버튼 위쪽에 이렇게 넣는 거야.
그리고 주문 버튼 눌렀을 때 빈칸이면: const roomNumber = document.getElementById('room-number').value.trim(); if (!roomNumber) { alert('객실번호를 입력해주세요.'); return; } 이렇게 주문 자체가 넘어가지 않게 만들면 돼. 다국어도 현재 4개 언어를 쓰니까 나중에 문구는 예를 들어 객실번호 / Room Number / 客室番号 / 房间号로 같이 맞추면 되고. 그리고 기존 ?room=301 기능을 완전히 삭제하는 것보다는 남겨두는 걸 추천해. 예를 들어 URL에 객실번호가 있으면 입력칸을 자동으로 채우고, 일반 QR로 들어오면 직접 입력하게 만들면 돼. 그러면 앞으로 필요할 때 객실별 QR도 다시 쓸 수 있어. 즉: 공용 QR 접속 ↓ 주문페이지 ↓ 메뉴 선택 ↓ 객실번호 직접 입력 ↓ 주문하기 ↓ Supabase orders room_number = 입력한 객실번호 이 방식으로 바꾸자. 다음은 index.html만 수정하면 돼. 지금 실제 운영 중인 index.html 파일 보내줘. 기존 메뉴·디자인·다국어·주문 기능은 안 건드리고 객실번호 입력 부분만 최소 수정해서 전체 코드로 다시 만들어줄게.
